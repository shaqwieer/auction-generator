# Builder + cover + table fixes — 2026-09-05

All seven landed. What follows is what each was and what was done.

Six problems reported from the builder. What each one actually is, and what
gets changed.

## 1. Every field box on the page canvas is mirrored

`placement()` emits `insetInlineStart`. The app sets `dir="rtl"` on `<html>`,
where that logical property resolves to `right` — but `NormRect.x` is
"distance from the **left** edge" (`from_points` divides `rect.x0` by the page
width). So every input box is drawn at `1 - x - w` instead of `x`.

Measured on the cover in the report: `auction_title` on غلاف 2 is stored at
x=0.000 w=0.517. The raster draws its text ending at 0.517 — correct. The input
box was observed spanning 0.485..0.995, which is exactly the mirrored rect
(1-0-0.517 = 0.483 .. 1.0). That is the "duplicate in another section with
border": one copy is the real render, the other is the mis-placed input.

Fix: `left` instead of `insetInlineStart`, in `pagecanvas.tsx` and in the admin
template editor (whose drag math already assumes x-from-left, so it disagreed
with its own rendering).

Confirmed in the browser against the app's own `dir="rtl"` document: a box of
width 51.67% at `inset-inline-start: 0` lands on 0.483–1.000, and at `left: 0`
on 0.000–0.517 — the second being where the renderer puts that field.

## 2. The value is drawn twice even when the box is right

The page underneath is the authoritative render. The input on top also paints
its value, in a substituted font. Once the box is aligned the two overlap and
smear.

Fix: the overlay input's text is transparent unless it has focus. The raster is
the preview; the input is an editing affordance, which is what its own
docstring already says.

## 3. Typing is interrupted; the page flashes and focus is lost

Three separate causes:

- `disabled={busy}` on the on-page inputs. A debounced save sets `busy`, the
  focused input goes disabled, and the browser drops focus.
- `AuthImage` calls `setUrl(null)` on every `src` change, replacing the image
  with a grey pulse until the new blob arrives — the "reload".
- `useEffect(() => setDraft(stored), [stored])` re-clobbers the draft when the
  save returns, dropping keystrokes typed while it was in flight.

Guarding the draft is not enough on its own. The debounce timer closes over the
render that scheduled it, so a save landing while somebody keeps typing left the
next patch carrying the revision from *before* that save — which the server
refuses, correctly, and the refusal reloads the page. That is the reported
symptom, arrived at from the other direction. The current revision is kept in a
ref that every `setPlan` writes, and the timer reads that.

## 4. Cover chooser appears twice

Step 1 (`/projects/new`) and the builder both show all eight covers. The step-1
panel goes; the عدد العقارات input inside its header moves up beside the project
name (it is the lot count — deleting the panel with it would create every
project with zero properties). The builder's cover panel becomes collapsible.

## 5. Covers: six, and no uploads

The chooser offered eight: the export's own cover page (a duplicate of غلاف 1),
غلاف 1–6, and a blank carrier for a client-supplied cover. Only غلاف 1–6 are
standard, so the carrier page and its `cover_image` field are no longer built,
and the export's own cover page is flagged `source_cover` so the builder can
place the cover node where the designer put it without offering it as a choice.

The one thing left for the user to see with their own eyes: log in and type on
a page. Everything above is verified by test, by render, or in the browser, but
nobody has driven the builder end to end since the change.

## 6. «تاريخ المزاد» prints on none of the six covers

The cover rule takes white run #1 whole. On غلاف 1/2/3/6 that run is two lines —
the printed label *and* the date — so baking redacts the label with it
(confirmed: the label is gone from `background.pdf` p15). On غلاف 4/5 the label
was never in the artwork.

Fix: the field is the **last line** of the run (geometry, not text), so the
label survives as design; and the missing label is drawn into the background of
غلاف 4/5 at build time, using the font, size, colour and offset measured from
the covers that have it. Flagged in the manifest as `drawn_label` so it can be
dropped when corrected artwork arrives.

## 7. «بيان العقارات» is one table, not two

The guide's blank specimen (p13) numbers the green block 01–08 **and** the navy
block 01–08 — they restart. The example page repeats the same ten sample rows in
both. And the guide's own text says overflow repeats the *page*
(«فيتم تكرار الصفحة»), not "use the second block".

So the two blocks are the two colourways of one table, and the current build is
wrong twice over: it prints rows 1–10 green and 11–20 navy on the same page, and
it claims 20 rows of capacity where the design has 10.

Fix: build the table page as two alternatives sharing `slot="lot_table"`,
`layout="green"` and `layout="blue"`, each carrying one block at the position
the designer puts the table — directly under the heading. The حضوري export has
both blocks; the إلكتروني/هجين export ships only the green one, so its navy
variant is stamped from the حضوري export's own navy block (same page size, same
column geometry), the way the electronic booklet already borrows two pages from
the hybrid. Nothing is recoloured: the navy block that prints is the one the
designer drew, with its sample rows cleared before it is placed.
